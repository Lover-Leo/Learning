# 浏览器国际象棋（第四阶段）

这是一个 React 国际象棋网页，支持本地双人和人机对战。在人机模式中，Stockfish 负责电脑走棋、实时局面评分、玩家走子质量，并在玩家主动请求时提供逐层展开的教学提示。

所有棋局规则、电脑计算和局面分析都在浏览器本地完成，不需要账号、后端或付费 API。

## 主要技术

- React + TypeScript + Vite
- chess.js：唯一可信的棋局规则和状态
- react-chessboard：棋盘显示、拖动及点击走棋
- Stockfish.js 19 WebAssembly：电脑走棋和局面分析
- 两个独立 Web Worker：对弈 Worker 只负责电脑走棋；分析 Worker 调度实时评分和主动提示
- Vitest：规则、异步流程、评分解析和走子分类测试
- 普通 CSS：优势条和响应式布局

## 安装与启动

```bash
cd D:\code\chess
pnpm install
pnpm dev
```

打开终端显示的网址，通常是 `http://localhost:5173`。

## 人机对战与实时分析

1. 在棋盘上方选择“人机对战”。
2. 选择执白、执黑或随机颜色。
3. 选择电脑难度。
4. 保持“实时分析”开启。
5. 等待电脑棋手和分析引擎加载完成后开始走棋。

模式、颜色、难度和分析开关都会保存在浏览器 `localStorage` 中。本地双人模式默认不运行分析，避免把它变成真人对局中的实时辅助工具。

关闭“实时分析”会停止当前分析并释放分析 Worker；再次开启时会重新加载。分析失败不会阻止正常走棋，可以在优势条区域点击“重试分析”。

## 如何阅读优势条

- 白色区域变大：白方更有优势。
- 黑色区域变大：黑方更有优势。
- 各占一半：局面接近均势。
- `+0.35`：白方大约领先 0.35 个兵值。
- `-1.80`：黑方大约领先 1.80 个兵值。
- `白方 M3`：白方拥有若干步内的强制将杀。
- `黑方 M2`：黑方拥有若干步内的强制将杀。

全局评分永远采用**白方视角**：正数表示白方占优，负数表示黑方占优，不会随着当前行棋方改变含义。

优势条使用双曲正切函数将评分平滑映射到有限范围，极端评分不会把页面撑开。强制将杀会显示为接近满格，但数据中仍保留 `mate` 类型，没有伪装成普通兵值。

Stockfish 的 `lowerbound` 和 `upperbound` 会标记成“暂定边界”，并使用 `≈`，不会显示成精确结论。

## 玩家走子质量

只评价玩家的走法，不评价电脑走法。系统会比较：

1. 玩家走棋前，在最佳走法下可以获得的评分。
2. 玩家实际走棋后，对手最佳应对下的评分。
3. 两个评分统一转换成玩家视角后的差值。

`评分损失 = 走棋前最佳评分 - 走棋后的评分`，最低为 0。

| 评分损失 | 标签 |
| ---: | --- |
| 0～20 cp | 最佳 |
| 21～50 cp | 优秀 |
| 51～100 cp | 良好 |
| 101～200 cp | 不准确 |
| 201～400 cp | 失误 |
| 大于 400 cp | 严重失误 |

点击棋谱中带标签的玩家走法，可以查看实际走法、引擎首选走法、走棋前后评分、评分损失和分析深度。

这些阈值是本项目自己的初始启发式规则，不等同于 Chess.com、Lichess 或其他平台的算法。分析深度、设备速度和局面复杂度都会影响结果。

## 三级按需提示

提示只在人机模式、玩家回合、实时分析已开启且分析引擎就绪时可用。点击侧栏的“获取提示”后，内容会逐级展开：

1. **思考方向**：只告诉你应关注将军、吃子、王的安全、中心或出子等经过局面验证的主题；不会显示格子、记谱或答案。
2. **关键棋子**：告诉你应重点观察哪一枚己方棋子，并高亮它的真实起始格；仍不会画出完整走法箭头。
3. **完整答案**：显示 Stockfish 首选走法、起点和终点、棋盘箭头、评分、PV 线路，以及最多三个 MultiPV 候选走法。

这种逐层展开方式让初学者先自己思考，再按需要获得更多信息。三级提示中的候选按钮可以切换：棋盘只预览相应箭头，不会替你落子，也不会改变真实棋局。

- **SAN** 是棋谱中容易阅读的标准代数记谱，例如 `Nxe5+` 表示马吃到 e5 并将军。
- **PV**（主要变化）是引擎认为双方较好应对下可能出现的一小段后续线路。
- `≈` 表示 Stockfish 返回的是 lowerbound/upperbound 边界评分，不是精确结论。

提示解释由 Stockfish 候选结果和 chess.js 能验证的事实生成，例如将军、将死、吃子、升变、王车易位、进入中心或完成出子。无法可靠识别具体原因时，页面会使用保守说明；项目没有接入大模型，也不会凭空声称存在叉攻、牵制或必胜战略。

提示使用情况与走子质量是两个独立字段。请求过提示后，该玩家棋步会在棋谱中显示“已使用提示 L1/L2/L3”；这不会改变第三阶段的客观质量标签。较短分析时间可以快速给出有用建议，但不能保证在所有复杂局面中绝对最优。

提示失败时可以点击“重试提示”。你也可以随时取消提示或直接走棋；迟到的结果会因对局编号、FEN、行棋方、棋谱步数和请求编号不匹配而被忽略。每个提示局面最多缓存 12 份，键中包含 FEN、MultiPV 数、深度和 Stockfish 版本。

本地双人模式禁用实时提示，避免它成为同屏真人对局的即时最佳走法辅助工具。

### 将杀局面的分类

将杀评分不会强行换算成一个很大的 cp 数字：

- 找到引擎首选或保留自己的强制将杀：最佳或优秀。
- 错过原本拥有的强制将杀：严重失误。
- 让对手获得强制将杀：严重失误。
- 从必败将杀中逃脱：不会误判成严重失误。
- 胜负性质不变、只有将杀步数轻微变化：采用保守分类。

## 五档电脑难度

| 等级 | 名称 | Skill Level | 最大深度 | 每步时间 |
| --- | --- | ---: | ---: | ---: |
| 1 | 入门 | 0 | 3 | 约 120 ms |
| 2 | 简单 | 4 | 5 | 约 250 ms |
| 3 | 中等 | 8 | 8 | 约 500 ms |
| 4 | 困难 | 14 | 12 | 约 900 ms |
| 5 | 专家 | 20 | 16 | 约 1500 ms |

这些只是相对难度，不代表准确 Elo。实时分析使用独立的快速设置：单线程、8 MB Hash、深度 11、约 700 ms 时间限制；主动提示使用 MultiPV 3、深度 10、约 900 ms 时间限制。

## 首次加载与故障排查

首次进入人机模式时，浏览器需要加载并编译 Stockfish WebAssembly。开启实时分析时会创建第二个独立 Worker，因此普通设备可能需要等待几秒。提示复用这个分析 Worker，不会再创建第三套 Stockfish。

如果电脑棋手或分析加载失败：

1. 点击对应区域的“重试加载”或“重试分析”。
2. 使用较新的 Chrome、Edge、Firefox 或 Safari。
3. 必须通过 `pnpm dev` 启动，不能直接双击 `index.html`。
4. 重新运行 `pnpm install`，确认 `public/stockfish` 中包含 JS、WASM 和许可证。
5. 内存较小的设备可以关闭实时分析，正常对弈仍然可用。

## 悔棋和异步安全

- 本地双人每次撤销一步。
- 人机模式通常撤销玩家和电脑的一整个回合。
- 电脑或分析正在计算时，悔棋、重开、切模式、换颜色或关闭分析都会让旧请求失效。
- 每个分析结果都检查对局版本、FEN、棋谱步数和请求编号，迟到结果不能污染新棋局。
- 分析缓存最多保留 24 个局面，避免内存无限增长。
- 任务优先级为：电脑走棋、玩家主动提示、实时评分；提示结束后会恢复当前局面的普通评分分析。

## 测试与构建

```bash
pnpm test
pnpm typecheck
pnpm build
```

真实浏览器 Stockfish 检查（需要 Chrome 或 Edge）：

```bash
pnpm smoke:stockfish
```

该检查会实际启动两个 Stockfish Worker，验证 UCI 初始化、合法电脑走法、初始局面有效评分、三级提示、MultiPV 候选、SAN 和箭头、提示使用标记、玩家走子标签以及主线程仍能持续响应。
